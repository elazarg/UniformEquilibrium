# Strict inertness and pure better-response cycles: initial triage

## Status

Initial assessment only. The proposed strict-inert consumer is false as
written. A small conditional finite-graph lemma survives, so the incoming note
has nonzero internal value. It is not an export candidate.

## Proposed conclusion

The incoming argument claims that a strict normalized-inert cap, whose unique
exact product root is all Continue, supplies a binding singleton coordinate.
It then constructs a positive cycle of pure one-stage better responses and
identifies that cycle with a positive cumulative punishment-floor admissible
payoff return.

Both arrows require facts not supplied by the strict object.

## First gap: the asserted exact-root sequence is absent

The binding argument starts from exact roots `x_n != allContinue` at caps
`b_n -> b`, where `b` is the strict inert cap. Closedness and uniqueness would
indeed force `x_n -> allContinue`, and strict singleton slack at every
coordinate would eventually force `x_n = allContinue`, giving a contradiction.
Under that additional sequence hypothesis, some binding coordinate

```text
b_k = r_k({k})
```

would follow.

But `FinFourNormalizedStrictInertSingleDensityToll` stores only:

- the normalized-return capstone;
- strict excess of its whole debt over the global minimum; and
- uniqueness of all Continue among exact roots at the limiting cap.

The normalized passport carrier is generated by arbitrary literal prefix
roots. Its approximating raw decorations do not assert that their roots are
exact Nash roots for nearby caps, much less that they are non-all-Continue.
Thus the sentence “the normalized-return data retain the binding witness” is
not justified by the inspected interface.

The conditional binding lemma may still be useful if a strict-ray or another
actual source later supplies such a nontrivial exact-root sequence.

## Surviving finite graph lemma

Fix a continuation vector `b`. For each coalition `S`, put

```text
V_b(empty) = b,
V_b(S) = r(S) for nonempty S,
g_i(S) = V_b(S triangle {i})_i - V_b(S)_i.
```

For a pure root `S`, exact root Nash is equivalent to

```text
g_i(S) <= 0 for every i.
```

Consequently, if all Continue is the unique exact root and some coordinate
binds, `b_k = r_k({k})`, then:

- `empty -> {k}` is a zero-gain toggle;
- every nonempty coalition has a strictly profitable toggle; and
- finiteness of the Boolean cube produces a closed toggle walk with strictly
  positive total designated-player gain.

This is a correct static better-response-cycle statement. It concerns the
finite pure root game at the fixed continuation vector `b`.

## Fatal gap: better-response toggles are not admissible Bellman edges

`QuittingPositiveCumulativeAdmissiblePayoffNearReturnFamily` requires paths in
`quittingPunishmentFloorAdmissibleChargedRelation`. Every edge of that relation
contains an exact `IsQuittingNashBellmanEdge`:

```text
current payoff = the Bellman successor payoff of one root and its tail;
the root is an exact Nash root against the tail payoff;
both boxed states satisfy the punishment floor.
```

The constructed toggle leaves a pure coalition precisely because a player has
a profitable unilateral deviation. Its source pure root is therefore *not*
an exact Nash root. A payoff comparison

```text
V_b(S triangle {i})_i > V_b(S)_i
```

does not manufacture either the required Nash root or the Bellman successor
identity between consecutive boxed states.

Moreover, cumulative charge in the checked relation is literal root
absorption mass, not the sum of designated players' payoff improvements.
Repeating the static better-response cycle therefore does not create the
`chargeSum` field demanded by the near-return consumer.

This invalidates the central inference

```text
positive pure better-response cycle
  -> positive cumulative admissible-payoff near-return.
```

## Strongest honest conclusion

With an independently supplied binding coordinate, strict uniqueness of all
Continue yields a positive finite pure better-response cycle at the inert cap.
This is static root-game geometry only. It neither consumes the strict-inert
node nor produces Output 2.

To become useful dynamically, one would need a separate realization theorem
that replaces each profitable toggle by an exact punishment-floor
Nash–Bellman path while matching successive payoff states. That theorem is
essentially the missing chronology producer and cannot be inferred from the
toggle inequalities alone.
